# Documentation layout implementation plan

Goal: Generate a smaller, evidence-backed living documentation tree with a visible
`GENERATED BY AIKYA HARNESS` footer, canonical feature/architecture paths and an actual-file index.

Base: develop 3e35e7f. Branch: refactor/documentation-layout. SDD integration is not
merged into this develop reference; this change preserves that baseline rather than
silently introducing SDD code from another branch.

## Contract

- All newly generated living Markdown uses the exact visible footer, not the old leading comment.
- Feature folders are lowercase under features/; architecture document 03.-arquitectura.md belongs in architecture/.
- Keep initialization and actual toolchain findings in root overview.md, not harness/bootstrap.md.
- Rename the documentation harness area to tools, holding token-policy.md, agents.md and conditional skill-comparison.md only. Runtime paths .harness/ and aikya/scripts/harness/ are not renamed.
- Testing plans belong in plan/testing.md.
- Generate indice.md from actual existing Markdown files; do not list nonexistent placeholders.
- Existing-project analysis creates only pages supported by observed/configured data. Architecture and overview provide actual profile/module evidence; do not invent missing application behavior.
- skill-comparison.md is written only after an explicit external-skill installation command, never during onboarding, plan or status. Preserve /aikya-skills-install and support requested alias /aikya-install-skill.
- Preserve customized documents and runtime files. Managed legacy paths are migrated with backups and a preview; customized collisions block instead of overwriting. Read-only analysis never migrates or indexes.
- Engineering documentation remains English; existing en/es living-doc policy is preserved.

## Tasks

1. Add regression tests for footer placement, canonical feature paths, init/analyze architecture paths, sparse analysis, conditional comparison, index contents and custom/symlink safety. Run them before implementation.
2. Add docs_layout.py as the shared document-path, footer, index and conservative migration utility. Expose reviewed write/index/normalize operations without shell execution.
3. Adapt localized templates and installer to the shared layout, fold initialization guidance into overview.md, move testing and agent documentation, and suppress unsupported pages.
4. Update analysis previews/ownership manifests and approved writes; ensure no generated paths differ from the preview. Back up managed legacy documents and keep customized content intact.
5. Update skill-install commands and actual attempt reporting, keeping plan/status side-effect-free for comparison generation.
6. Update documentation guards and workflow instructions so they enforce the new paths without requiring empty stubs. Include indice.md after actual document changes.
7. Run complete tests on Python 3.10–3.13, catalog/runtime/profile smoke checks and independent review; commit locally on the requested new branch. Do not merge or push without a request.

Acceptance: fresh init and approved existing-project analysis produce no harness/ documentation folder, bootstrap document, root-level feature-v2 folder or unconditional comparison. Actual documentation links resolve; content and language policy are preserved across repeat runs. Custom-file conflicts remain visible and read-only modes do not write.
