# Defect diagnosis and repair
1. Read the actual code, incident details and relevant tests; reproduce the failure if safe.
2. State and verify root-cause hypotheses before editing.
3. Propose and apply the smallest approved fix; add a regression test.
4. Do not run external services, destructive commands or production operations without separate approval.
5. Report real test evidence, limitations, changed files and remaining risks.
6. Update bugs/bugs.md and affected change documents under aikya/docs/ in the configured language.

Respect user approvals, preserve custom files, do not install dependencies or access external systems without separate authorization. Report tests actually executed, blocked checks and evidence. Living documentation under aikya/docs/ follows .aikya/docs-policy.json; all other content is English.

Every Markdown document generated by Aikya, wherever it is saved, must end with
the exact line `GENERATED BY AIKYA HARNESS`. Keep frontmatter first and add the footer once.

## Reproducible bug records

Use the `docs-md/bug-report` catalog template. After approved diagnosis, write a
reviewed report to `aikya/docs/bugs/bugs.md` through documentation_templates.py write.
Require a unique BUG-NNN, title, summary, environment/build, reproducible steps,
expected result and actual result. Include sanitized evidence, scope/impact,
workaround and suspected cause only when supported. Distinguish hypotheses from
verified findings. Existing reports append without replacing prior bug entries.
Do not create an empty register during init or analyze; never use bugs/index.md.
