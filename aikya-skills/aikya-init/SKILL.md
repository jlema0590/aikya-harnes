# New project initialization
1. Resolve the project-scoped Aikya CLI and probe the workspace. Reject existing code and redirect to /aikya-analyze.
2. Interview project_type and required stack decisions; mode is always new.
3. Ask one additional question: choose en or es for living documentation under aikya/docs/ only.
4. Validate the profile and preview the operation; approval is required for writes and external operations separately.
5. Invoke CLI init --docs-lang en|es after approval. Preserve historical profile keys and document toolchain requirements.
6. Suggest /aikya-doctor, /aikya-scaffold plan and /aikya-quality.

Respect user approvals, preserve custom files, do not install dependencies or access external systems without separate authorization. Report tests actually executed, blocked checks and evidence. Living documentation under aikya/docs/ follows .aikya/docs-policy.json; all other content is English.
