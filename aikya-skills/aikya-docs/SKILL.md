# Living documentation maintenance
1. Read only the affected source and Aikya pages.
2. For informational requests with no changes, do not create artificial docs updates.
3. Use .aikya/docs-policy.json to select en or es exclusively under aikya/docs/.
4. Update affected overview, security, architecture, operations, quality and change-log pages from verified evidence.
5. Record performed tests; preserve modified team docs and stable filenames/links.
6. Validate docs with the local docs guard and show any failing gates.

Preserve project instructions and customized assets. Never claim tests, security reviews or deployments succeeded without execution. Scope external operations separately. Living docs follow .aikya/docs-policy.json; other engineering text stays English.

## Canonical living documentation

Create only documents backed by actual decisions, implementation or analysis evidence.
Use lowercase feature folders under `aikya/docs/features/<feature-name>/`; never create
feature folders at the docs root. Keep `03.-arquitectura.md` in `aikya/docs/architecture/`
and test plans in `aikya/docs/plan/testing.md`. Initialization belongs in root overview.md.
Use the installed `python3 aikya/scripts/harness/docs_layout.py write --root . --path <relative-md> --input <reviewed-content> --approved`
for approved document writes; it routes feature/architecture paths and adds the exact
`GENERATED BY AIKYA HARNESS` footer. Preserve custom documents and report conflicts.
After any other approved Markdown changes run `python3 aikya/scripts/harness/docs_layout.py index --root . --approved`
so indice.md lists actual files, then run docs_guard. Do not refresh docs for read-only requests.
